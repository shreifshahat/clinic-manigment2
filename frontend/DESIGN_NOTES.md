# ملاحظات التصميم (الواجهة)

## 1. القرارات

| القرار | السبب |
|---|---|
| Next.js 15 App Router + TypeScript strict | مطلوب من المواصفة؛ App Router يناسب لوحة داخلية خلف تسجيل دخول. |
| Server Components فقط عند الحاجة، والصفحات التفاعلية Client Components | لا SSR/ECM مطلوب لنظام داخلي؛ التفاعل (النماذج، الاستعلامات) يحتاج عميلًا. |
| TanStack Query لحالة الخادم | تخزين مؤقت، إعادة محاولة، تعطيل الإرسال المكرر، وإلغاء الطلبات — بدل كتابة ذلك يدويًا. |
| React Hook Form + Zod v4 | تحقق من النماذج في المتصفح + نفس قواعد التحقق المطبّقة في الخادم. |
| مكتبة UI صغيرة مكتوبة يدويًا | لا مكتبة مكوّنات ⇒ حزمة أقل ومخاطرة أقل وتحكّم كامل في RTL. |
| `Intl` بدل مكتبة تواريخ | `Intl.DateTimeFormat` مع المنطقة الزمنية من الـ API يكفي، وبدون حزمة إضافية. |
| لا حالة إدارة عالمية (Redux/Zustand) | لا حاجة: حالة الخادم في TanStack Query، وحالة الجلسة في سياقين فقط (`auth`, `clinic`). |
| لا `date-fns`/`luxon`/`moment` | intermediates؛ `Intl` كافٍ ودقيق مع المناطق الزمنية. |

## 2. RTL

- `<html lang="ar" dir="rtl">` في التخطيط الجذري.
- أدوات Tailwind **المنطقية** فقط: `ms-`/`me-`/`ps-`/`pe-`/`text-start`/`text-end`
  (لا `ml-`/`mr-`/`left-`/`right-`).
- الأرقام والرموز (أرقام الفواتير، أوقات الجهاز) داخل جدول RTL تُلفّ بـ`dir="ltr"`.
- الخط: `Noto Kufi Arabic`/`Noto Sans Arabic` مع بدائل النظام.
- الأرقام تُعرض بالأرقام العربية-الهندية عبر `Intl` مع `ar-EG` (وهو ناتج
  `Intl` لا اختيار يدوي).

## 3. إدارة الحالة

```
AuthProvider      → جلسة Supabase + رمز الوصول (متصفح فقط)
  └── ClinicProvider → GET /auth/session + GET /meta/clinic
        └── Page → useQuery/useMutation حسب الحاجة
```

- `api.ts` يحتفظ بالرمز في متغيّر وحدة ويضيفه لكل طلب.
- `ClinicProvider` يعيد تحميل الجلسة تلقائيًا عند انتهاء الرمز (403/401) عبر
  `signOut()`.
- `staleTime` مضبوط: 30 ثانية للبيانات العامة، 5 دقائق لبيانات العيادة.

## 4. إتاحة الوصول (a11y)

- تسمية مرتبطة لكل حقل عبر `<Field>` الذي يمرّر `id` و`aria-describedby`
  و`aria-invalid` تلقائيًا.
- رسائل الخطأ `role="alert"`، والرسائل غير الخطية `role="status"` +
  `aria-live="polite"`.
- رابط «تخطّي إلى المحتوى الرئيسي» (`skip-link`) يظهر عند التركيز بالكيبورد.
- حلقة تركيز واضحة (`:focus-visible`) في كل العناصر التفاعلية.
- الأزرار التي تنفّذ عملية جارية: `aria-busy` + تعطيل.
- الجداول تستخدم `<th scope>` و`<caption>` عبر `TableWrapper`.
- الألوان: تباين كافٍ على الخلفية الفاتحة، والاعتماد على النص لا اللون وحده
  (حالة الإلغاء/التعليق تُنصَّ أيضًا).

## 5. حالات العرض

كل شاشة تمرّ بأربع حالات: **تحميل** (مؤشر + `role="status"`)، **فارغة**
(رسالة صريحة + لا أرقام افتراضية)، **خطأ** (رسالة الخادم العربية +
`request_id` + زر إعادة محاولة)، **نجاح** (رسالة خضراء). لا شاشة بيضاء أبدًا.

## 6. الأداء

- First Load JS ≈ 103 kB مشترك + 3–7 kB لكل صفحة (Next.js 15 + route splitting).
- `QueryClient` واحد للتطبيق كله.
- لا صور أو خطوط خارجية (الخط من النظام) ⇒ لا طلبات خارجية.

## 7. الأمان في الواجهة

- ترويسات CSP و`X-Frame-Options` و`nosniff` و`Referrer-Policy` في
  `next.config.ts` (تُغلق `connect-src` على نطاق الـ API ومزوّد المصادقة).
- لا `dangerouslySetInnerHTML` في أي مكان.
- لا أسرار في المتصفح: `service_role` لا يظهر في أي `NEXT_PUBLIC_*`.
- الأخطاء لا تعرض تفاصيل داخلية: `normalizeError` لا يعرض `detail` في أخطاء
  5xx، و`ErrorState` تعرض رسالة الخادم + `request_id` فقط.
- **تحذير**: إخفاء عناصر التنقل ليس ضابطًا أمنيًا — الفرض في الخادم.

## 8. ما لم يُنفَّذ عمدًا

- لا بوابة مرضى ولا صفحة عامة.
- لا محادثة أو اتصال مباشر.
- لا تخزين محلي للرموز (لا `localStorage` للرمز) — الجلسة في Supabase فقط.
- لا PWA/Service Worker (خارج النطاق).
- لا مكتبة رسوم بيانية: الجداول والبطاقات تكفي للتقارير المطلوبة.
