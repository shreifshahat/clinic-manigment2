# مصفوفة الصلاحيات

> هذا الملف **مولَّد** من `backend/app/core/permissions.py`.
> للتحقق: `python backend/scripts/generate_permissions_doc.py --check`
> (`docs/PERMISSIONS.md` محدث فقط إذا طابق المخرجات).

## كيف تُطبَّق الصلاحيات (ثلاث طبقات مستقلة)

| الطبقة | ما تُنفّذه | Where |
|---|---|---|
| 1. العملية (Operation) | هل يستطيع الدور تنفيذ العملية أصلًا؟ | `app/core/permissions.py` → `require_permission(...)` في طبقة الـ API **و** إعادة فحص في طبقة الخدمات |
| 2. السطر (Row) | أي السجلات يَرى هذا الدور؟ | سياسات **RLS** في PostgreSQL (`migrations/versions/20261020_2110_row_level_security.py`) |
| 3. الحقل (Field) | أي الحقول تظهر في الاستجابة؟ | الإسقاط (projection) حسب الدور في `app/schemas/*` و`app/services/patients.py` |

> إخفاء الزر في الواجهة **ليس** ضابطًا أمنيًا. الطبقتان 1 و2 تُطبَّقان على الخادم
> وقاعدة البيانات، والواجهة مجرد عرض.

## معنى الرموز

- `●` — مسموح (بعد تطبيق قيود الصفوف والحقول).
- `—` — غير مسموح؛ الطلب يُرفض بـ `403 FORBIDDEN` (أو `404` إذا كان السطر
  غير مرئي أصلًا للدور، حتى لا يُكشف وجود السجل).

## قيود إضافية خارج المصفوفة

| القيد | التفصيل |
|---|---|
| **صاحب العيادة لا يرى المحتوى الطبي** | لا توجد سياسة RLS تسمح له بقراءة جدول `visits` إطلاقًا، ولا policy تقريبية. لا يمكن حتى عدّ الصفوف. |
| **الريسبشن لا يرى المحتوى الطبي** | نفس الكلام: لا policy لجدول `visits` لغير الطبيب. |
| **الطبيب لا يرى مرضى أطباء آخرين** | `visits_select` و`patients_select` تشترط `doctor_staff_id = app_current_staff_id()`، أو تفويضًا صريحًا في `visit_access_grants`. |
| **التفويض الصريح** | يُمنَح من الطبيب صاحب الملف أو من صاحب العيادة، ويُسجَّل في `visit_access_grants` مع السبب ووقت الانتهاء، ويُقرأ في `audit_log`. |
| **صاحب العيادة يرى بيانات هوية مصغّرة** | في財務ياته يرى `id` + الاسم فقط (بلا هاتف ولا تاريخ ميلاد). في `patients` لا يظهر حقل الهاتف أصلًا. |
| **الريسبشن يرى إجماليات الفاتورة فقط** | نقطة `/billing/invoices/totals` و`/billing/invoices/{id}` تُعيد `{total, paid_amount, remaining_amount, payment_method}` بلا بنود. |
| **الطبيب يرى فواتير عمله فقط** | `invoices_select` تسمح للطبيب فقط إذا كان الموعد أو الزيارة تخصّه (`app_can_read_invoice`). |
| **المصروفات لصاحب العيادة فقط** | سياسات RLS على `expenses` و`expense_categories` تقصر القراءة والكتابة على `owner`. |
| **سجل التدقيق لصاحب العيادة فقط** | `audit_log_select` محصورة في `owner`، ولا توجد سياسة `UPDATE`/`DELETE` إطلاقًا (سجل غير قابل للتعديل). |
| **إدارة الحسابات** | `staff:create` و`staff:disable` لصاحب العيادة فقط. لا يستطيع أي مستخدم تعديل كود النظام أو إعدادات الأمان. |
| **الحقول المالية المثبتة لا تُعدَّل** | مشغِّلات قاعدة البيانات (`app_guard_invoice_update` …) تمنع تغيير `total`/`amount`/`unit_price` … إلا بصاحب العيادة؛ الإصلاح = إلغاء موثّق + قيد جديد. |

## تدفّق الفحص في طلب واحد

```
Authorization: Bearer <token>
   │
   ├─ 1) التحقق من الرمز مقابل JWKS الخاص بـ Supabase
   ├─ 2) جلب صف `staff` عبر دالة SECURITY DEFINER (app_staff_by_auth_id)
   ├─ 3) ضبط app.user_id و app.role داخل المعاملة (set_config … is_local=true)
   ├─ 4) فحص أن الحساب مُفعّل وأن الجلسة غير ملغاة
   ├─ 5) require_permission(...)  ← الطبقة 1
   ├─ 6) RLS أثناء كل استعلام   ← الطبقة 2
   └─ 7) إسقاط الحقول حسب الدور ← الطبقة 3
```
