# تعريف التقارير

> كل رقم في التقرير مشتق من سجلات قاعدة البيانات. لا توجد قيم محسوبة في
> الواجهة ولا أرقام افتراضية.

## 1. المصطلحات

| المصطلح | التعريف الدقيق |
|---|---|
| **المتحصلات (collected)** | مجموع الدفعات التي حالتها `recorded` ووقت استلامها (`received_at`) داخل الفترة. الدفعات الملغاة (`void`) مستثناة. |
| **المصروفات المسجلة (expenses)** | مجموع المصروفات التي حالتها `recorded` ووقتها (`incurred_at`) داخل الفترة. المصروفات الملغاة مستثناة. |
| **إجمالي الفواتير (invoiced)** | مجموع `total` للفواتير التي حالتها ≠ `void` ووقت إصدارها (`issued_at`) داخل الفترة. مستقل تمامًا عن التحصيل. |
| **المستحق غير المحصّل (outstanding)** | `invoiced − collected` لنفس الفترة. تقدير لاستحقاقات الفترة، وليس ديونًا عالمية. |
| **صافي النتيجة (net)** | `collected − expenses`. |
| **الفترة (period)** | من `00:00:00` إلى `23:59:59.999999` بتوقيت العيادة (`CLINIC_TIMEZONE`) في التاريخين الأول والأخير. |

## 2. التقرير الأسبوعي — `GET /api/v1/reports/weekly`

**النافذة الافتراضية:** آخر 7 أيام شاملةً حتى اليوم (بتوقيت العيادة).
يمكن تمرير `start`/`end` (ISO date) أو `days`.

**البنية:**

| الحقل | المعنى |
|---|---|
| `period` | النافذة المستخدمة |
| `currency` | عملة العيادة |
| `invoiced_total` | إجمالي الفواتير الصادرة في الفترة |
| `collected_total` | المتحصلات الفعلية في الفترة |
| `expenses_total` | المصروفات المسجلة في الفترة |
| `net_result` | `collected_total − expenses_total` |
| `outstanding_total` | `invoiced_total − collected_total` |
| `invoice_count` / `payment_count` / `expense_count` | أعداد |
| `appointment_count` | عدد المواعيد التي بدأت في الفترة |
| `completed_visit_count` | عدد الزيارات المكتملة (`is_completed`) في الفترة |
| `no_show_count` / `cancelled_count` | حالات المواعيد |
| `collected_by_method` | التحصيل مفصّلًا: `cash` / `visa` |
| `daily[]` | صف لكل يوم: الفواتير، المتحصلات، المصروفات، الصافي، عدد المواعيد |
| `notes` | تذكير دائم بأن الصافي **ليس** ربحًا محاسبيًا |

### ما لا يدخل في التقرير
- الدفعات الملغاة، المصروفات الملغاة، الفواتير الملغاة.
- الإهلاك، المصروفات المستحقة غير المدفوعة، قيمة العمل غير المنجز، الضرائب
  (غير مُنفَّذة)، تكلفة البضاعة.
- **لذلك لا يصح استخدام `net_result` كـ«ربح»** في أي قرار مالي أو ضريبي.

### مثال عملي
```
إجمالي الفواتير 4,000.00 | المحصّل 3,250.00 | المصروفات 1,200.00
صافي النتيجة = 3,250.00 − 1,200.00 = 2,050.00   (مؤشر تشغيلي)
المستحق في الفترة = 4,000.00 − 3,250.00 = 750.00
```

## 3. أداء الأطباء — `GET /api/v1/reports/doctors`

لكل طبيب في الفترة:
`appointments` (عدد مواعيده)، `completed`، `no_show`، `cancelled`،
و`invoiced_total` (الفواتير المرتبطة بمواعيده في الفترة).

> **ملاحظة:** لا يحتوي التقرير على أي محتوى طبي — الأرقام مبنية على
> المواعيد والفواتير فقط، فلا يخرق سرية المريض.

## 4. تقرير الجداول — `GET /api/v1/reports/schedule`

لكل (طبيب × يوم) في الفترة: `total`, `pending`, `confirmed`, `in_progress`,
`completed`, `cancelled`, `no_show`.

## 5. توضيحات تهم التفسير

| السؤال | الجواب |
|---|---|
| هل `invoiced_total` = الأرباح؟ | لا. هو قيمة ما صدر من فواتير، لا ما حُصّل ولا ما netto. |
| لماذا يظهر تحصيل少于 من الفواتير؟ | فرق طبيعي (دفعات جزئية، آجل، فواتير أُلغيت خارج الفترة). |
| هل المصروفات تشمل رواتب الأطباء؟ | نعم، **إذا سُجّلت كمصروف**. النظام لا يسجّل الرواتب تلقائيًا — تُدخلها يدويًا. |
| لماذا يختلف تقرير اليوم عن تقرير الأسبوع؟ | لأن النافذة مختلفة؛ وتقرير «اليوم» غير منفّذ (النافذة = آخر 7 أيام). |
| هل الأرقام تتأثر بتوقيت 입력 السجل أم بتاريخه؟ | بتاريخه: `issued_at` / `received_at` / `incurred_at` (تاريخ الوثيقة) لا تاريخ الإدخال. |
